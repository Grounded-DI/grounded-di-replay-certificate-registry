# Frozen synthetic contract v1
All identifiers, units, quantities, temperatures and minutes are fictional. Thresholds 2–8 C inclusive and [0,60) minutes are fixture assumptions, not safety standards. Six planned shipments have quantities 4,3,2,5,2,3 and destination clinic; fixture.json freezes all records.

Receipt status: missing if none; duplicate if more than one; otherwise matched if destination matches, wrong_destination otherwise. A duplicate is one physical receipt at most: use the smallest reported quantity, capped at planned quantity; do not count duplicate evidence twice. Wrong-destination and missing receipts confer zero known units. For a single correctly bound receipt, known units are min(received, planned); unknown is planned minus known. Known receipt is not an inventory acceptance.

Temperature status: missing when no complete contiguous nonoverlapping coverage of the window is present; violation if any covered segment exceeds the inclusive fictional limits; otherwise within. Observations must be whole integer minutes and C, and fully inside the window. For known units, accept only a unique correctly bound receipt, exact planned quantity, and within-range complete temperature coverage; otherwise hold. Unknown units remain unknown. Outcome includes total accepted, held, unknown and sorted unresolved reasons: receipt_missing, duplicate_receipt, wrong_destination, quantity_discrepancy, temperature_violation, temperature_missing. Suppress temperature_missing when receipt itself is missing or wrong destination. Quantity discrepancy applies only when exactly one correctly bound receipt differs from plan. For duplicate receipts report duplicate only, plus temperature status if deficient.

Canonical JSON is ASCII-escaped UTF-8, recursively sorted keys, compact separators, newline. No process metadata. Seven records: 1 fixture; 2 receipt statuses; 3 temperature statuses; 4 known/unknown units; 5 accepted/held/unknown by shipment; 6 totals and unresolved reasons; 7 ordered SHA-256 hashes for records 1–6. The final record is a commitment, not independent verification. expected/ and expected_hashes.json were manually specified before running the implementation.

Dependencies Python 3 standard library. Commands: python3 producer.py fixture.json DIR; python3 checker.py fixture.json DIR; python3 controls.py; python3 compare.py. Acceptance: two distinct fresh processes match all seven expected files directly by bytes and SHA-256 and one another; each checker passes; eight registered controls execute and pass with no errors or skips; clean extraction reruns all checks; archive saved and identity verified. The project checker shares specification, fixture, host and Python, and is not external verification.

Controls frozen: temperature violation, missing temperature evidence, changed destination, quantity discrepancy, duplicate receipt, legitimate change to S1 quantity and matching receipt, altered intermediate file, wrong final totals plus recomputed commitment. Controls assert explicit statuses/quantities or checker rejection. Tamper controls test checker, not a live downstream action. Missing required results or crashes are not passes.
