# Frozen contract: synthetic invoice reconciliation

Repository starting commit: 45967f8569ad3e56c47bcdb7b2a018ceac6401cd. Benchmark reference SHA-256 497614c00216d7fe86886afdfd93aa7c08a5d65a590c38dd8a78e5380d80fa98. The reference is a frozen Ulam benchmark; this is a separate synthetic example, not a replay of it.

Problem: prepare a payment batch and hold duplicate invoice identifiers within a vendor. All data and policies are fictional. Values are integer cents. Input row order controls which duplicate is first. Each invoice total is quantity times unit price. The first vendor+invoice pair is eligible if its total does not exceed the purchase order limit; all later occurrences are held as duplicates, even if their amounts differ. Equality to the limit is eligible. The control is batch-local and does not detect historic duplicate payments, fraud, taxes, or real purchasing authority.

Input: A/101 quantity 3 price 1200 limit 4000; B/202 quantity 2 price 2500 limit 5000; A/101 quantity 3 price 1200 limit 4000; C/303 quantity 4 price 1000 limit 3500. Expected amounts 3600, 5000, 3600, 4000; statuses PAY, PAY, HOLD_DUPLICATE, HOLD_LIMIT; payable 8600, held 7600, total 16200 cents. Manual check: 36+50=86 dollars; 36+40=76; 86+76=162.

Seven boundaries generated separately by each process: 01 normalized input, 02 line arithmetic, 03 purchase-order limits, 04 duplicate classification, 05 disposition, 06 ledger totals, 07 decision and integrity manifest of 01-06. Boundaries 01-06 are computed stage records; 07 packages their identities and totals. Matching hashes establish byte identity, not accuracy. Every boundary is UTF-8 JSON, sorted keys, compact separators, ASCII escaping, final LF, integer values only. Comparison requires direct byte equality and SHA-256 equality across runs. Tolerance zero. Python 3.12.14 standard library; no network or third-party dependencies. Output directory must not exist; receipts including timestamps and PIDs remain outside compared stage files.

Tests registered before execution: unittest methods test_expected, test_limit_equality, test_altered_input, test_altered_output, test_coherent_wrong_result. No skips permitted. Altered input changes downstream amounts; altered output must fail against original manifest; limit equality is eligible; coherent wrong-result control recomputes manifest over altered data and demonstrates identity alone accepts it while a manual expected-result check rejects it. The manual check is project-internal and shares the specification and arithmetic assumptions, not third-party certification.

Release requires both runs and all seven direct-byte/hash comparisons to pass; expected arithmetic and all five tests to pass with no errors/skips; clean reproduction; complete candidate manifest and inventory; rights and privacy audit; unchanged head; exact remote verification. Public files: this contract, input.json, demo.py, test_demo.py, README.md, run1 and run2 outputs, run receipts, comparison and test logs, manifest and release record. SHA256SUMS.txt excludes itself; its membership and actual files must be independently reconciled. No private runtime material is included.
