# Arsenic source-to-report replay — 2026-11-04

EPA's National Primary Drinking Water Regulations table lists the arsenic MCL as 0.010 mg/L effective as listed from January 23, 2006. EPA's Chemical Contaminant Rules page identifies community and non-transient non-community systems. Source URLs, short preserved excerpt, scope and compliance caveats are in frozen/SOURCE.md. EPA guidance describes arsenic reporting to the nearest 0.001 mg/L for compliance; this demonstration uses exact, unrounded numbers solely for a mathematical comparison. In particular the 9.999 and 10.001 µg/L boundary results are not regulatory compliance outcomes. A single sample cannot be equated to a compliance conclusion; specific monitoring, confirmation, annual averages and potential early triggers can matter.

Fixture, source record, specification and independently calculated expectations were written before implementation and baseline execution. The challenge plan was written after the initial baseline runs and before the challenge suite. Source record is a short attributed excerpt and links; the full source page bytes were not archived. There is no externally authenticated timestamp.

Two fresh producer processes produced matching bytes for all six boundaries, and the separately implemented checker accepted each. SHA-256 values are in evidence/test_results.json. The 28-case suite passed 28, failed 0, skipped 0, with no uncaught runner errors. The suite aborts on an uncaught exception rather than recording case-level errors; it completed normally. It contains 6 byte comparisons, 2 checks, 1 hand-expected comparison, and 19 challenge/process cases. The result file records commands, expected and actual statuses/exits, and directory contents before and after. Replay comparisons use the captured runs; use the README commands with fresh paths to repeat generation.

Recalculated commitments do not rescue altered outputs against the original input. A coherent replacement of input and generated artifacts is accepted, because the checker trusts its input. Source validation enforces an exact local source identity and threshold, but does not re-fetch the webpage or prove the source is current, authentic, applicable to a real system, or accurately extracted. Source and fixture are unsigned. Producer and checker are independent source files with no shared imports, but share Python standard libraries, schema, canonicalization and the same interpretation; shared mistakes remain possible. The sixth boundary commits to the preceding five, it does not independently verify them. The checker ignores extra files in an output directory. The producer rejects existing destinations but file writes are not atomic and I/O failure can leave a partial new directory. No concurrent execution guarantees.

All inputs and system data are fictional. No real lab data, actual compliance decision, health assessment, outside integration or payment is included. A real buyer must supply provenance, laboratory QA, sample context, legal applicability, rounding, and qualified human review.
