# Frozen scenario and contract — 2026-11-04
Synthetic commercial equipment accidental water-damage claims. One policy P1, one claimant C1, one item of evidence per claim. All money is integer US cents. This is an illustrative ruleset, not an insurance product or coverage opinion.

Policy P1 covers accidental_water; intentional_damage is excluded. Deductible 10,000 cents; covered payment = min(max(claim amount - deductible, 0), coverage limit 100,000 cents). Adjuster authority is 50,000 cents inclusive. A payment of zero is held for review. Covered positive payment above authority is held, not paid. Payment route creates no payment.

Decision order: (1) validate exact schema, nonnegative integer amounts (booleans excluded), unique claim IDs; malformed input exits 2 with INVALID_INPUT and creates no artifacts. (2) For each claim, require exactly one evidence record; duplicate, missing, contradictory, or mismatched claim/policy binding means HOLD / EVIDENCE_MISSING, EVIDENCE_DUPLICATE, EVIDENCE_CONFLICT, or BINDING_MISMATCH, in that precedence. (3) complete evidence cause must match claim cause; mismatch means EVIDENCE_CONFLICT. (4) intentional_damage means DENY / EXCLUDED_CAUSE; other noncovered cause means DENY / NOT_COVERED. (5) covered claim calculates amount; 0 means HOLD / ZERO_AMOUNT; above authority means HOLD / AUTHORITY_EXCEEDED; otherwise ROUTE_PAYMENT / COVERED_WITHIN_AUTHORITY. Holds and denials have disposition amount 0; calculation retains provisional amount when calculable. Evidence status missing/conflicting prevents coverage from becoming a final decision. Ordered reasons contain exactly one code in this narrow ruleset.

Input: JSON object policy {id, covered, excluded, deductible, limit, authority}, claimant {id}, claims array of {id, policy_id, claimant_id, cause, amount, evidence:[{claim_id,policy_id,cause}]} . Identifiers and causes are nonempty ASCII strings; policy rules covered/excluded are unique nonempty ASCII strings with no overlap. Unknown keys rejected. Strict UTF-8 JSON, duplicate object keys rejected; no floats, NaN, BOM, or unpaired surrogates; integer amounts 0..1000000000. References must match the policy/claimant; wrong claim policy or claimant is BINDING_MISMATCH as is an evidence binding. Claims sorted by id and evidence by (claim_id, policy_id, cause); policy lists sorted. JSON artifacts encoded UTF-8, ASCII escaping, sorted keys, separators comma/colon no spaces, single newline. Seven files named 01_inputs.json ... 07_commitment.json. 01 contains normalized input, 02 coverage classification for each claim (classification only; not final), 03 evidence and binding statuses, 04 provisional amounts and authority checks, 05 decisions and reasons, 06 synthetic dispositions, 07 SHA-256 of exact bytes of 01–06 keyed by filename. Commitment is not independent verification.

Checker independently recomputes all seven boundary objects from supplied input and compares canonical bytes. It rejects missing or mismatched artifacts with CHECK_FAILED exit 1; malformed input is INVALID_INPUT exit 2. It relies on the supplied input and policy as truth, not external authentication. Producer creates a new output directory only; existing destination rejected with OUTPUT_EXISTS exit 2, preserving contents. On invalid input no directory is created. Unexpected I/O is an error exit 3; no transaction or concurrency guarantee. Checker is read-only. Both use Python standard library, shared JSON schema/serialization specification and SHA-256, no code imports shared. Test targets include fresh-process replay, expected decisions, policy/evidence mutations, malformed inputs/artifacts, coherent forgery, serialization, duplicate keys, existing output and rerun. Acceptance: all specified tests pass without skips, bytes of all 7 boundaries match, and checker accepts both runs. No production or certification claim.
